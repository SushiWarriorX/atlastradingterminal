## Implemented but NOT verified against the real service

- Coinbase, Yahoo (`yfinance`) and FRED adapters against the live endpoints.
- **Telegram against the real api.telegram.org**: verified only against mocks and a local fake of the Bot API. The request shape follows the documented Bot API (`sendMessage`, `getMe`, `retry_after`), but a first real test message is the check that matters (Settings > Send test message).
- Yahoo daily-bar download (`yf.download` batches) and the live Nasdaq Trader directory fetch used by the scanner: only mocked/fixture-tested. Throughput and rate limiting for the full ~8k-symbol universe are unmeasured.
- **Paper fills against real market behaviour**: the simulator's spread, slippage, fee and participation assumptions are defaults, not measurements; nothing here has been compared with real executions. Portfolio analytics were only run on demo/constructed data.
- **IBKR against a real TWS / IB Gateway.** Everything was tested against a fake that mirrors the ib_async API surface the adapter uses (the real `Stock`/`MarketOrder`/`LimitOrder`/`StopOrder`/`StopLimitOrder`/`ExecutionFilter` classes are used, so object construction is real). Attribute names and behaviour (status strings, `commissionReport` timing, `orderRef` round-trip, the `1.79e308` "unset" commission) follow ib_async's documented model but have not been exercised against a live session. Do a first run with a paper account and one share.
- **The Variational CSV format.** Variational documents CSV exports (trades with type trade/liquidation/settlement, funding, realized P&L, transfers) but `docs.variational.io` could not be reached from the build sandbox, and its API keys are not currently offered (mainnet is in private beta). The preset is a best guess from a search summary: column aliases are fuzzy, the mapping is shown for you to correct, and nothing is saved until you confirm.
- **IBKR Flex Query column names** (`DateTime`, `Buy/Sell`, `TradePrice`, `IBCommission`, `IBExecID`, ...) are from memory of IBKR's documented trade fields, not from a real export. Same safeguard: preview and an editable mapping.
- **Journal statistics on real trade history** (only synthetic and hand-built data so far).
- `AnthropicLLM` against the real API (only the scripted fake was exercised), so prompt quality, JSON-compliance rate and token costs are unmeasured.
- The AI desk's technical agent (now including the MTF block) has never been run with a real model.

## Not built (shown in the UI as "Not built yet", never with fake data)

Alerts: email and Discord delivery (only the `Notifier` interface exists; Telegram is built), news/earnings/macro/BTC-derivatives alert types (need those data sources), range-exit/break-of-structure/trend-reversal/volatility-expansion alerts, a `cross` check between consecutive bars (alerts compare state between checks, so a spike that reverts between two checks is missed), server-push (the UI polls every 8 s). Journal: trade-level screenshots captured from the chart (you attach an image file), tags/mistakes analytics beyond counts, volatility-regime breakdowns, Sharpe/Sortino (needs an equity time series, not trade P&L), tax lots, options strategies as multi-leg trades, corporate-action adjustment of imported history. Variational: any API integration (none is offered; Hyperliquid is covered by its public API instead), automatic sync of exports. Hyperliquid: spot symbol names (`@107` style indices are kept as given), history beyond the API's ~10,000 most recent fills, builder-fee attribution, automatic scheduled sync. IBKR: market data via IBKR (quotes still come from Yahoo/Coinbase), options/futures/crypto/FX orders, multi-account, Flex Web Service download (CSV import only). Trading: anything live (broker adapters, real order routing), shorting/margin, extended-hours simulation, bracket/OCO orders (a planned stop is only used for risk sizing; it does not create a protective order), fractional-share venues, multi-currency, tax lots (average cost only), corporate actions on positions, the AI Strategy and Risk agents, the trade journal, and risk-limit enforcement at FILL time (checks run at submit). Scanner: news-catalyst, earnings-momentum and sector-rotation presets, fundamental/market-cap/sector (outside the core list) filters, intraday time-of-day RVOL, scan alerts, AI ranking/explanations, virtualized results table, historical scan evaluation. Backtester: intraday bars, parameter optimisation or walk-forward re-fitting (the hold-out is a fixed chronological split, nothing is fitted), dividend adjustment, delisted symbols (survivorship), multi-leg or options strategies, BTC (equity universe only), testing journal setups (journal trades carry no machine-readable rule). News: sentiment, impact scoring and AI summaries (deliberately absent: they would be invented numbers over untrusted text), a `news_catalyst` scan preset, news alerts, full-text articles, paid/licensed feeds, clustering beyond title similarity, and a news tool for the AI agents (headlines are attacker-influenced text and need injection-hardening before any model sees them). Also not built: trade ideas, portfolio, risk, journal, alerts, BTC derivatives (OI, funding, liquidations, basis, ETF flows, on-chain), fundamentals/earnings/filings, Fed/CPI dashboards and economic calendar, breadth/heatmap/regime, multi-timeframe analysis and technical score, drawing tools and annotations, crosshair sync, price-based (non-return) compare overlay, order book and trades, streaming AI responses, news, scanner and strategy agents (news: headlines are untrusted text; strategy: would drift into trade recommendations; scanner: adds little beyond the deterministic explanations), agent memory across sessions, streaming agent output, paper/live trading, Postgres/Redis/workers, CI e2e.
